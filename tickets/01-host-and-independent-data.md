# 01：统一宿主与独立数据启动

**What to build:** 建立可独立构建和启动的工具套件。启动后仅有一个常驻 WPF 宿主和一个托盘，右键能打开设置与退出；数据和身份与原三个应用隔离，重复启动保持单实例。

**Blocked by:** None (can start immediately)

**Status:** resolved

**实施结果：** 已实现独立 Core/WPF 宿主、动态模块契约、独立设置与单实例、按需设置及单托盘。Release 构建和隔离控制入口/真实 WPF 功能检查已通过。正式 EXE 的 UAC 确认/拒绝与真实鼠标托盘点击未执行，明确留待人工整合验收；详见 [验证记录](../docs/validation/ticket-01.md)。

**规格：** [工具套件合并规格](../spec.md)。主要覆盖用户故事 2–5、11、12、36、39。

## 已确认约束

- 新代码、文档、测试、安装脚本及构建产物均位于整合目录，原三个项目保持不动。
- 整合素材使用当前工作区，包含便签尚未提交的修改；记录选用的源版本与工作区差异，避免后续只复制提交版本而漏掉修改。
- 一个管理员权限常驻宿主承载三个工具；本票先交付可验证的宿主，后续工单接入各工具。复用原核心与平台模块，不启动三个旧 EXE 作为常驻实现。
- 套件独立数据、独立单实例和安装身份，从空白开始；不读取或修改原用户数据、旧程序和旧启动项。

## 验收条件

- [x] 套件可独立构建及启动，运行不依赖原项目的构建输出或开发机绝对路径；所有生成产物在整合目录内。
- [ ] 正式宿主要求管理员权限；手动启动拒绝 UAC 则本次不启动整个套件。不保留性能条原独立提权交接链。（manifest 已实现，真实 UAC 待人工）
- [x] 启动后只有一个套件托盘和一个常驻 WPF 宿主；不预先显示首页。
- [ ] 托盘左键和双击均不呼出工具；右键能打开按需创建的统一设置并安全退出。（菜单及退出检查通过，真实鼠标待人工）
- [x] 默认主题跟随系统，三个工具的启用偏好首次为开启，开机启动首次关闭；尚未接入的工具在中间版本中显示不可用，不伪装运行。
- [x] 为模块提供宿主真实使用的启动、命令、保存预检、停止与重建入口，为后续工单预留清楚的接入位置。
- [x] 第二次启动通知已有套件实例，不产生第二图标或进程；不显示剪贴板、不强制打开便签，可用统一设置反馈。
- [x] 套件数据位置和单实例身份与原工具分离；原应用运行不被误判为套件实例。
- [x] 隔离数据的空白启动、配置保存恢复、重复启动和退出功能检查通过；记录管理员权限中未实际运行的人工场景。

## 验证方式

通过真实宿主启动、托盘命令、配置重启和临时存储结果验证。沿用已有存储和单实例适配中适用的测试；仅验证对调用方可观察的行为，不依赖宿主内部字段。
