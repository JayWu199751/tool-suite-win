# 02：快捷键驱动的文字历史与粘贴

**What to build:** 在统一宿主内记录文字历史，通过全局快捷键呼出或收起面板，选择文字后复制并粘贴回原输入窗口；可以调整快捷键并停用、重新启用剪贴板。

**Blocked by:** 01 — 统一宿主与独立数据启动

**Status:** resolved

**实施结果：** 剪贴板作为宿主模块接入，默认 `Ctrl+Shift+V` 呼出/收起、统一设置改键与占用冲突提示、文字历史持久化与粘贴回原窗口、停用后停止记录并注销快捷键均已实现。`ClipboardTool.Tests` 481 条（排除桌面类）与 `ToolSuite.ClipboardUiChecks` 文字链路场景通过；真实管理员窗口粘贴与真实按键演示未执行，见[工单 09 验证](../validation/ticket-09.md)。

**规格：** [工具套件合并规格](../spec.md)。主要覆盖用户故事 13 的文字链路及 14、17–19。

## 已确认约束

- 剪贴板作为同一 WPF 宿主中的模块运行，保留原有领域规则和必要后台线程，不创建第二个 Application、独立托盘、自启入口或常驻应用进程。
- 仅使用套件自己的历史和配置存储；原剪贴板数据及设置不自动读取、迁移或修改。
- 面板通过快捷键呼出，托盘左键和双击无动作，右键剪贴板组不增加面板呼出命令。

## 验收条件

- [ ] 启用期间记录文字历史并持久化，重启后能从套件存储恢复；不影响原应用数据。
- [ ] 默认 Ctrl+Shift+V 呼出或收起面板；呼出仍保留原面板的焦点、停靠和键盘操作语义。
- [ ] 通过统一设置更换快捷键，成功后新键生效；注册失败或被旧工具占用时明确提示，不强制结束旧程序或静默抢占。
- [ ] 选中文字能写入剪贴板、恢复原输入焦点并执行粘贴，普通目标和管理员目标的既有行为保留。
- [ ] 目标窗口失效、恢复焦点失败和粘贴失败按原结果契约报告，不向错误的当前窗口盲目注入。
- [ ] 停用前提交并保存，成功后停止记录并注销本模块快捷键；停用时按呼出键不自动重新启用。
- [ ] 重新启用能重新建立必要监听和快捷键，不出现重复记录、重复事件或无法再次呼出；不退出其他工具或整个宿主。
- [ ] 粘贴和回调使用必要后台执行与 UI 调度，未将阻塞操作迁移到 UI 消息循环。
- [ ] 文字历史、快捷键冲突、焦点与失败结果、启停重建和重启读取的对应功能检查通过。

## 验证方式

复用原剪贴板的历史、热键和粘贴链路测试，在隔离宿主和测试目标窗口中执行真实呼出及粘贴。真实管理员窗口路径若未运行，明确记录人工验证步骤与未执行状态。
