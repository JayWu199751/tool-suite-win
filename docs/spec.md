# 工具套件合并规格

**Status:** ready-for-agent

日期：2026-10-21。用户已确认产品行为、验证入口及九项工单的粒度和依赖。本文为正式实施规格，尚未开始实现。

## 问题说明

剪贴板历史、性能悬浮条、清单便签目前是三个独立 WPF 应用，分别安装、常驻托盘和管理启动退出。用户希望统一为一个安装包和一个托盘入口，在保留现有能力的同时尽量减少常驻内存与无用后台工作。

## 解决方案

使用一个常驻管理员权限 WPF 宿主承载三个可独立启停的工具，保留剪贴板面板、性能条、多张便签各自的窗口形态。托盘左键不绑定操作，剪贴板保持全局快捷键呼出；右键菜单分组管理三个工具，并提供统一设置、开机启动与退出。

新套件使用独立数据，从空白开始。旧应用、旧数据及旧启动项不自动修改。首版集中完成应用合并与资源按需使用，保留功能测试；不安排专项内存对比，内存表现由用户日常使用判断。

3. 作为用户，我希望左键点击托盘图标不呼出窗口，以便继续只通过快捷键呼出剪贴板。

6. 作为用户，我希望分别启用或停用工具并记住选择，以便不使用的工具停止后台工作。
7. 作为用户，我希望关闭或隐藏一个窗口不会退出整个套件，以便其他工具继续工作。

9. 作为用户，我希望保存失败时停用不生效并保留当前状态，以便处理失败后再重试。

11. 作为用户，我希望新套件从空白数据开始，以便与原三个工具保持独立。
12. 作为用户，我希望原应用及原数据保留，以便仍能独立使用旧版。

14. 作为用户，我希望默认通过 Ctrl+Shift+V 呼出或收起剪贴板，并能修改快捷键，以便符合自己的使用习惯。

18. 作为用户，我希望快捷键被占用或粘贴失败时看到明确结果，以便调整快捷键或手动完成操作。
19. 作为用户，我希望停用剪贴板后不再记录或响应呼出键，以便停用状态不会被一次按键意外改变。
20. 作为用户，我希望性能条保留 CPU、内存、GPU、显存、网络速度和时间的原有显示与配置，以便继续观察系统状态。
21. 作为用户，我希望硬件或驱动不支持的指标显示缺失而不阻断其他指标，以便性能条仍能工作。
22. 作为用户，我希望关闭某项指标后停止不再需要的查询，以便减少无用后台开销。
23. 作为用户，我希望性能条保留全屏自动隐藏、手动显隐、贴靠和多显示器位置恢复，以便不干扰当前任务。
24. 作为用户，我希望隐藏性能条时暂停采样、恢复后重建基线，以便减少后台工作且不会出现异常网络速率。
25. 作为用户，我希望首次运行便签时创建空白便签，以便直接开始记录清单。
26. 作为用户，我希望便签保留创建、改名、编辑、完成、删除、排序和独立强调色，以便继续现有工作方式。
27. 作为用户，我希望每张便签仍能独立移动、调整大小、屏幕贴边和便签间贴边，以便组织桌面。
28. 作为用户，我希望关闭便签表示隐藏，托盘可按标题重新打开，以便内容不会随窗口消失。
29. 作为用户，我希望隐藏便签的窗口保存后释放，重新打开时内容与布局保持，以便减少隐藏界面的占用。
30. 作为用户，我希望便签原有的手动备份导入、导出和损坏恢复能力保留，以便保护套件内新建立的数据。
31. 作为用户，我希望三个工具共用浅色、深色和跟随系统偏好，以便外观一致。

33. 作为用户，我希望设置与导入界面在需要时打开，关闭后释放，以便避免闲置窗口常驻。

35. 作为用户，我希望开机启动只运行已启用工具并恢复套件保存的状态，以便不重新开启停用的工具。
36. 作为用户，我希望重复启动不会产生第二个套件实例或第二个托盘图标，以便避免重复后台工作。
37. 作为用户，我希望退出前保存各工具内容，保存失败时保留运行状态并告知原因，以便不会静默丢失编辑。
38. 作为用户，我希望保留原有键盘操作、多显示器/DPI 和辅助功能表现，以便合并后仍适合日常使用。
39. 作为用户，我希望功能检查使用隔离数据，以便测试不改动原应用或日常套件数据。
40. 作为用户，我希望内存优化以单进程、按需创建与及时释放资源落实，以便日常使用保持轻量，同时不要求专项内存对比报告。

## 实现决定

### 宿主与模块

- 一个常驻 WPF 应用进程、一个 Application、一个 UI 消息循环、一个托盘。复用已有领域规则、存储、平台适配和窗口实现，保留原模块与程序集边界，减少不必要的重写。
- 将各原 App 的装配逻辑提取为宿主可管理的模块入口，覆盖启动、命令、保存预检、停止与重建。宿主集中决定进程退出；停用单个工具不会调用全局 Shutdown。
- 模块具有可区分的启用、停用和启动失败状态。真实启动成功后才显示为运行；失败给出可操作提示并允许重试。启动失败不伪装成功，也不强制结束其他正常运行工具。
- 第一次启动启用三个工具，剪贴板面板按需呼出，性能条显示，便签按原有首次使用规则建立空白便签。后续仅恢复套件保存的数据和状态。
- 停用先提交编辑、捕获布局并保存，成功后再释放运行资源及持久化停用状态；失败则保留可恢复的当前状态，不丢弃未保存内容。启用后恢复停用前的窗口可见性。
- 三个工具都停用时，套件继续保留唯一托盘和设置入口，用户可重新启用；不保留各工具的后台工作。

### 权限与启动身份

- 正式宿主统一要求管理员权限，以保留向管理员窗口快捷粘贴的能力；便签等同进程功能也随宿主提权。手动启动拒绝 UAC 时本次整个套件不启动。
- 性能条不再执行其独立应用原有的自动 runas、跨权限接管和拒绝后普通权限运行链。该行为变更已在合并讨论中确认，原项目代码保持不动。
- 套件使用独立的单实例、自启和安装身份，不将原应用识别为套件实例，也不接管或删除旧身份。
- 重复启动通知已有套件实例，保持启停及窗口可见状态，不因此显示剪贴板或强制打开便签；可以在已有套件中显示统一设置作为反馈。
- 原剪贴板若占用呼出快捷键，套件明确提示冲突并允许通过设置更换；不终止原程序或静默抢占。

### 托盘、主题与设置

- 托盘左键和双击不绑定工具显示动作；剪贴板呼出依旧使用全局快捷键。右键按三个工具分组提供管理能力和启停状态，并提供统一设置与退出；剪贴板分组包含启停、快捷键和清空历史等管理动作，不另设面板呼出动作。
- 统一设置按需创建，不增加常驻首页。工具停用时仍能在设置中启用或调整可离线保存的配置，但不会由设置编辑或快捷键隐式启用。
- 套件统一保存浅色、深色、跟随系统偏好，首次跟随系统；模块的旧主题字段不成为独立权威。每张便签的强调色仍独立。
- 共用主题状态和必要系统监听，模块样式局部应用，不按全局字典固定索引覆盖其他模块资源。保留系统高对比度与文字大小适配。
- 开机启动首次关闭，统一开关只注册套件自己的启动项，启动后恢复已启用工具的状态；不修改原应用启动项。注册或注销失败时如实显示，不把失败记成已生效。

### 数据与兼容

- 首版使用套件独立的用户数据根目录，各模块拥有独立存储区域，统一设置单独保存。复用旧模型和存储代码时必须注入新位置，不能回退到旧应用默认目录。
- 新套件首次启动不读取、复制或修改原应用的数据和设置；不会自动迁移、切换前备份、卸载原应用、处理原启动项或将旧便签状态当作新状态恢复。
- 保留原有数据可靠性能力，包括原子保存、损坏恢复、便签手动备份导入/导出及导入前确认与必要内部备份；这些功能只作用于套件数据或用户主动选择的文件。取消的是自动旧版迁移流程。
- 便签导入只影响便签内容及布局，保留套件主题、自启和工具启停状态。替换全部前确认；追加导入产生独立副本。
- 卸载套件保留用户数据，不删除原应用数据，不影响原安装与启动项。

### 内存与后台资源

- 优先共享宿主基础设施，保留剪贴板监听、钩子和串行执行的必要线程及原有顺序契约，不把所有后台工作压到 UI 线程。
- 隐藏便签先提交编辑、捕获布局并保存，成功后回收对应窗口、视图模型和事件订阅，再次打开按需重建。保存失败保留未保存状态；隐藏与删除的语义不变。
- 设置、导入等界面按需创建，关闭完成后释放窗口实例与不再需要的计时器、事件和引用；重建后配置和交互正常。
- 剪贴板记录与面板视图分离；保留可视项加载、按显示尺寸解码、有界缩略图缓存、收起后解除位图引用与作废在途结果。呼出仍应保持流畅。
- 性能条仅查询已启用指标需要的数据源；关闭 GPU 与温度等相关指标时不执行无用查询。保留隐藏暂停采样、恢复后重建差分基线及在途结果隔离。
- 工具停用与整个套件退出均取消任务、停计时器、退订静态事件、释放钩子、监听、管道、图标和原生窗口；再启用安全重建，退出后没有残留工作或锁。
- GPU 采样可以保留现有短命查询子进程，必须可超时取消并释放；首版不要求改写硬件查询技术。

### 安装与工程范围

- 首版按三个工具共同支持的 Windows 11 x64 范围整合，统一自包含安装包携带一份兼容的 .NET 10 桌面运行时。
- 新源码、文档、测试、安装脚本与构建产物统一位于已指定的整合目录，原三个项目保持不动；使用便签当前工作区内容，不能只复制最后一次提交而丢掉现有修改。
- 套件可独立构建、测试和打包，不依赖原三个目录中的运行时产物或开发机绝对路径。
- 升级套件自身时检查套件文件占用，保持数据；安装、升级、卸载只操作套件自身范围。

## 测试决定

### 已确认的主要验证入口

以套件真实使用的控制入口执行工具启停、配置变更和退出，以用户侧快捷键、托盘命令及窗口交互验证显示与行为；用临时数据目录观察保存及重启结果。测试通过调用方真实使用的入口验证可观察结果，不依赖私有字段布局或内部方法调用顺序。

规则、存储、粘贴链路和指标源复用现有测试入口，不为合并重复建立同义抽象；只有宿主协调和跨工具行为增加整合验证。

### 功能覆盖

- 宿主：唯一实例、唯一托盘、左键无动作、右键命令、无常驻首页、统一设置与主题、全部停用时可恢复。
- 剪贴板：文字与图片记录、去重及上限、搜索、置顶、备注、撤销、呼出快捷键、快捷键冲突、管理员与普通窗口粘贴、失败结果及停用停止记录。
- 性能条：各指标选择、硬件缺失显示、只查询需要的数据源、手动和全屏显隐、采样恢复基线、多显示器/DPI、拖动与设置重建。
- 便签：清单编辑与排序、完成状态、窗口位置与贴边、单张和全部显隐、隐藏后重建、停用后恢复、手动导入/导出、损坏恢复及写入失败。
- 跨工具：一套主题不污染样式、停用一个工具不影响另两个、失败不伪装成功、保存失败时不丢数据、重复启停后行为正常、退出后资源及文件锁释放。
- 安装与自启：无预装桌面运行时也可启动、拒绝 UAC 的结果、独立安装与自启身份、默认自启关闭、启用选择重启恢复、旧数据未被访问或改动、套件卸载保留数据。

### 现有测试依据

剪贴板已有规则、存储、热键、焦点和粘贴链路测试及隔离 E2E 工具；性能条已有控制器契约、平台源及 WPF 窗口检查；便签已有独立数据检查、真实 WPF 桌面检查及启动退出脚本。复用适用内容，调整到新宿主、新存储位置和已确认行为。

开发检查使用隔离数据，不修改个人数据或真实开机启动项。必须触发 UAC、真实登录或依赖特定硬件的场景，使用明确的人工验收步骤并记录实际结果，未运行不标记通过。

### 内存判断范围

不建立专项内存基线、配对比较、固定 MB 上限、下降百分比或长期压力报告。保留低内存实现要求及对应功能检查，例如停用后无新查询、隐藏重建不丢内容、取消后没有迟到更新；内存表现由日常使用判断，未测量不报告节省数值。

## 范围外

- 自动读取、迁移、备份、接管旧应用数据，修改旧启动项或自动卸载旧应用。
- 新增云同步、提醒、跨工具内容联动，以及整体重做现有窗口界面。
- 每个工具独立明暗主题、独立托盘或独立开机启动开关。
- 拒绝提权后保留部分工具普通权限运行的双进程或多进程方案。
- 新增其他 GPU 厂商专用支持、改写硬件采样技术或保证所有硬件都有温度读数。
- 专项内存基准测试、旧三程序对比报告和具体节省数值承诺。
- 本次文档交付不包含应用实现；后续按已确认工单开展实施。
